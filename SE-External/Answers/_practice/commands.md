# Commands to run on the lab computer

Use Bash or Git Bash. Start each question from the submission root.

## Q3. Docker Nginx static page

Prerequisites are Docker with its engine running, access to pull the base image, `curl` or a browser, and free host TCP port `8081`. The commands assume `library-nginx` is unused as a container name and image tag.

```bash
docker version
cd nginx
docker build -t library-nginx .
docker run --name library-nginx -d -p 127.0.0.1:8081:80 library-nginx
docker ps --filter name=library-nginx
curl -i http://localhost:8081/
docker logs library-nginx
```

The build uses the current folder (`.`) as its context. The Dockerfile copies the static file to Nginx's document root. The `-p` option publishes host port `8081` to container port `80` for local access. If the first request arrives before Nginx starts listening, retry it.

Expected output is a successful image build, a running container with `127.0.0.1:8081->80/tcp`, an HTTP `200 OK` response containing **Welcome to the Library**, and an access log showing `GET /` with status `200`. Open `http://localhost:8081/` in the lab browser before cleanup.

```bash
docker stop library-nginx
docker rm library-nginx
docker rmi library-nginx
docker ps -a --filter name=library-nginx
cd ..
```

## Q4. Git feature branch, merge and log

Prerequisites are Git, a configured Git author name and email, and a fresh local directory. Run `git config --get user.name` and `git config --get user.email` to check your identity. If either is empty, set it to your own details with `git config user.name` or `git config user.email` inside the practice repository before committing. This exercise uses a local repository.

```bash
mkdir git-branch-lab
cd git-branch-lab
git init
git branch -M main
printf '# Library System\n' > README.md
git add README.md
git commit -m "Add library README"

git checkout -b feature/catalog
printf 'Search the catalog by title or author.\n' > catalog.txt
git add catalog.txt
git commit -m "Describe catalog search"

git checkout main
git merge --no-ff feature/catalog -m "Merge catalog feature"
git log --oneline --graph --all --decorate
git branch --merged main
git status --short --branch
cat catalog.txt
```

The handout's `git merge feature/catalog` would also merge this feature. `--no-ff` creates a merge commit so the feature branch is visible in the graph even when Git could fast-forward. Expected results are a graph with an initial commit, a feature commit, and a merge commit at `main`, plus a clean working tree and the catalog text on `main`. Commit IDs are generated by Git in the lab.

After capturing the graph, optionally delete the merged branch. The merge and its history remain on `main`.

```bash
git branch -d feature/catalog
cd ..
```
